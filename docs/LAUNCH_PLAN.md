# Launch plan and product-value test

Release: ScopeQuay v0.4 research alpha. The public GitHub repository is available.
A Product Hunt launch has not been submitted. No user reviews, sign-ups,
testimonials, revenue or viral-growth numbers have been manufactured.

Promise: **Test risky agent actions in a local sandbox.**
Demonstration: choose a suite, compare an ungated proposal with a gate, inspect
committed effects, then switch naive retry to verification and inspect duplicate
effects. Show the supplied-action/no-model label clearly. A separate actual local
agent mode needs a running installed model.

## Sequence

1. Dogfood the complete local workflow and record a real screen walkthrough.
2. Ask willing external developers to try the documented steps on an example or
   their own action context. These are proposed interviews, not completed research.
3. Observe time to first result, whether they understand the metrics, where they
   get stuck, and whether they return. Collect consent before sharing private cases.
4. Fix demonstrated onboarding failures and document boundaries.
5. Publish a clear alpha listing when it is ready for the intended audience.
   Use GitHub releases and a technical walkthrough first; Product Hunt and relevant
   communities are distribution options, not proof of demand. Follow each community's
   rules and avoid spam, fake reviews or vote manipulation.

Product Hunt's [official product-page guide](https://help.producthunt.com/en/articles/17834537-4-build-your-product-page)
requires a product link, name, tagline, description, logo, gallery material and
launch classification/role. Use the GitHub repository as a usable download route.
The provided wide wordmark is suitable for the site; a square listing asset is
still needed. Do not claim the static GitHub Pages guide is a hosted experiment app.

## Draft listing — not posted

Name: ScopeQuay

Tagline: Test risky agent actions in a local sandbox

Description: Compare action gates, inspect sandbox effects and reproduce recovery
failures before connecting an agent to real tools. ScopeQuay includes a local
experiment dashboard, Python CLI/SDK and an advisory review skill. Open-source
research alpha; cloud models and real business connectors are not enabled.

Maker comment: I built ScopeQuay to make an agent's proposed actions and their
effects easier to inspect. Start with a supplied-action suite that needs no LLM,
compare controllers, and examine wrong or duplicate effects in a simulated ledger.
If you have a supported local Ollama model, try bounded agent episodes separately.
The calibration candidate has not demonstrated an advantage; those negative
observations stay in the record. I would value feedback on whether the action and
recovery trail helps you diagnose a failure, and where the setup becomes confusing.

## What would justify expansion

Repeated use and specific unmet needs should drive integrations, provider adapters,
team review and cloud hosting. These require stronger authorization, isolation,
cost controls and operational design. Open-core paid features are a hypothesis;
pricing and product-market fit are not yet validated.
